## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reconciler → Postgres | Operator role writes projection rows; pgx errors bubble through controller-runtime workqueue |
| reconciler → K8s API | Status subresource write is best-effort; DB row is authoritative |
| CRD spec field → projection row | Pass-through; no value transformation that could obscure intent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Tampering | Spec.Scope round-trip | mitigate | CRD kubebuilder enum marker constrains `Spec.Scope ∈ {"object","directory"}` at admission (Phase 1); DB CHECK constraint `scope IN ('object','directory')` blocks any drift (Plan 05-02). Reconciler passes the value verbatim; no transformation. |
| T-05-04-02 | Tampering | concurrent reconciler stomp | accept | Single-replica Operator (§5.1 deployment topology, Phase 1 Recreate strategy); no concurrent writes to the same projection row. Multi-replica Operator would require leader election + version-bump CAS — explicit v1alpha1 backlog. |
| T-05-04-03 | Information Disclosure | jsonb condition columns | accept | metav1.Condition fields are all K8s-visible metadata; no plaintext credentials, no email, no internal IDs. Public via `kubectl describe environment` anyway. |
| T-05-04-04 | Denial of Service | DB-write failure cascades reconciler retries | mitigate | pgconn class 08/57 returns raw err (controller-runtime exponential backoff); non-transient errors wrap with `fmt.Errorf` and feed the workqueue at the configured backoff cap. Same shape as Phase 2 external_refs writes — proven scaling characteristics. |
| T-05-04-05 | Repudiation | projection row missing post-reconcile | mitigate | DB-first / K8s-best-effort discipline (D-Discretion): if DB UPSERT fails, the reconcile returns error and the entire reconcile is retried — both DB row and K8s status update happen together (or not at all). |
| T-05-04-06 | Information Disclosure | CS reads soft-deleted row content | accept | CS-09 explicitly mandates serving until full removal. Soft-deleted row's `last_successful_refresh` continues to gate via the staleness check (CS-10) — eventually returns 503 stale_cache_expired anyway. |
| T-05-04-SC | Supply Chain | no new external deps in this plan | accept | Plan adds zero direct dependencies (achdb + pgx already direct). |
</threat_model>
