    - `Get` flow:
      1. Compose key as `envCacheKeyPrefix + ns + "/" + name`.
      2. `raw, err := r.rdb.Get(ctx, key).Bytes()`. If `err == nil`: `json.Unmarshal(raw, &v)`. On unmarshal SUCCESS: return `&v, nil`. On unmarshal FAILURE: fall through (log nothing — silent fall-through matches teamsresolver pattern).
      3. On Redis error (any cause): fall through to singleflight loader. Do NOT log the Redis error (cache is best-effort; loud-logging on Redis-down would amplify noise).
      4. Singleflight: `v, sfErr, _ := r.sf.Do(key, func() (any, error) { return r.loader(ctx, ns, name) })`. Type-assert to `*EnvRow`.
      5. On loader error (sfErr != nil): return `(nil, sfErr)` — propagate to caller (Plan 05-05 maps this to 500/503).
      6. On loader nil result (`v == nil`): return `(nil, nil)` (room miss — environment doesn't exist). Do NOT write nil into the cache.
      7. On loader populated result: `marshaled, _ := json.Marshal(v)` then `_ = r.rdb.Set(ctx, key, marshaled, cacheTTL).Err()` (best-effort). Return `(v, nil)`.
    - Doc.go: package-level documentation citing D-07 + the 60s convergence-window decision (Operator updates the projection row; cache TTL absorbs the latency rather than explicit invalidation).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go process → Redis | Cache wire format is JSON; Redis is trusted infrastructure within the cluster |
| envcache.Get → caller (Plan 05-05) | Cache returns the EnvRow exactly as deserialized; no field scrubbing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | Redis-injected fake EnvRow | accept | Redis is an in-cluster trusted dependency; tampering with cache entries requires Redis access which is already authenticated via redis Password from Phase 3 D-09. If an attacker holds Redis creds, they hold the entire cache plane. |
| T-05-03-02 | Information Disclosure | cache key format | accept | `ach:env:<namespace>/<name>` exposes namespace + environment name to anyone with Redis access. No credentials, no team membership, no plaintext. Namespace/name pair is non-sensitive (also visible in `kubectl get environment`). |
| T-05-03-03 | Denial of Service | unbounded key space | mitigate | Cache keys are bounded by the count of Environment CRs × 60s TTL. Each CR ≈ a few hundred bytes JSON-serialized. Capacity ceiling: ~10K Environments × 1KB = 10MB — fits in any production Valkey deployment. |
| T-05-03-04 | Denial of Service | thundering herd on cache miss | mitigate | `golang.org/x/sync/singleflight` collapses concurrent misses on the same key to a single loader call (verified by `TestGet_Singleflight_DedupesConcurrentMisses`). 50 concurrent requests → 1 DB hit. |
| T-05-03-05 | Repudiation | stale read after Operator update | accept | Up to 60s eventual-consistency window between Operator UPSERT and CS cache eviction. D-07 documents this; it's the cache budget. For force-fresh reads, caller can bypass via direct `db.GetEnvironmentByName`. |
| T-05-03-06 | Information Disclosure | JSON-serialized payload includes resource_version | accept | resource_version is K8s-visible metadata (also in `kubectl get environment -o yaml`). Not sensitive. |
</threat_model>
