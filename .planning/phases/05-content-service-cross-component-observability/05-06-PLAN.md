**OBS-05 caller-label coverage at end of Phase 5:**
Per OBS-05 the shared `litellm_unreachable_total{caller}` counter must span all four callers. This plan REGISTERS the counter once per process with the label dimension `caller` pre-declared (the metric supports any label value). Inc instrumentation coverage at end of Phase 5:

| forwarder       | proxy/handlers.go LiteLLM transport error paths   | Task 2 shim swap |

| platform_api    | (registered-but-unused — see below)               | DEFERRED         |
| operator        | (registered-but-unused — see below)               | DEFERRED         |

**Why platform_api + operator Inc hooks are DEFERRED:**
- Platform API: existing Phase 3 handlers (`internal/platformapi/{environments,hydrate,admin,envkeys,auth}/handler.go`) already emit `audit.OutcomeLitellmUnreachable` as response body codes via `render.Error` + `audit.EmitAudit`, but they do NOT Inc a counter — the Phase 3 design treated litellm_unreachable as audit-only. Wrapping `litellm.Client` in a decorator that Inc's on transport errors would require ~17 method-wrappers (the Client interface has 17 methods, each with distinct error-classification semantics — e.g. ErrNotFound vs transport error vs ErrAlreadyExists). That is NOT a one-line mechanical decoration; it's a structural Phase 3 retrofit out of scope for Phase 5.
- Operator: existing reconcilers in `internal/controller/ach/` consume `litellm.Client` for §10.3 force-refresh; the error branches log + retry via controller-runtime workqueue but do NOT emit a litellm_unreachable counter. Same retrofit constraint.

The pre-declared caller dimension means a future phase landing the Inc hooks does NOT need a new metric registration — just call `litellmUnreachable.WithLabelValues("platform_api").Inc()` at the existing handler error branches. Plan 05-08 E2E spec MUST surface this gap in its dashboard-coverage subtest (assert the metric is registered with the expected label dimension; do NOT assert non-zero values for platform_api/operator).
