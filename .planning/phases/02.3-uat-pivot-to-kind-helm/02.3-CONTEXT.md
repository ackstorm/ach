## Implementation Decisions (final, post-re-pivot)

### Framework adoption

- **D-01-v3 (2026-05-20):** **Phase 02.3 re-scoped from "full tier-1/2/3 framework" to "incremental stdlib e2e expansion + docker-compose cleanup"**. The sister tier-2 framework adoption is rejected for ACH — the user accepted only the substrate (`e1b943c`), not the Ginkgo/tier-2/dev-loop superstructure. Phase 02.3 is now ~1-2 days of work (e2e test port + deletions + replan), not 4-5 weeks. Phase 3 unblocks immediately after this phase ships.

- **D-02-v3:** **Stay on stdlib `testing`, no Ginkgo migration.** The `test/e2e/phase{1,2}_invariants_test.go` pattern (TestMain bootstrap → t.Run sub-T → shell-out kubectl/psql) is the canonical e2e idiom for ACH. The new SC#5 test follows the same shape.

- **D-03-v3:** **No `test/tier2/` tree, no `config/uat/` overlay, no scripted Tier 3.** The existing `test/e2e/` + `config/e2e/` are the e2e surface. ACH-CRD manifest validation is implicit in the existing SC#1-5 tests; a dedicated `tier3-validate.sh` is not needed.

### Live-validation reachability

- **D-04-v3:** **In-cluster LiteLLM is the orphan-cleanup wire target.** The Phase 02.1 design decision that the e2e overlay points the operator at an *unreachable* LiteLLM (to defer SC#5 to docker-compose) is RETIRED. `cluster.sh` deploys LiteLLM v1.83.10 via the BerriAI Helm chart at `svc/litellm.litellm-system.svc.cluster.local:4000`; the `LiteLLMConnection/default` CR in `config/e2e/litellm_connection.yaml` references it; SC#5 is now reachable without docker-compose.

- **D-05-v3:** **OrphanReapLive scales operator to 0** while it runs, to avoid a race against the in-cluster orphan reaper revoking the orphan token before the test's in-process `TickOnce()` sees it. Cleanup restores `--replicas=1` and waits for rollout. Trade-off: brief loss of `dumpOperatorLogs` debuggability during the sub-T — accepted.

- **D-06-v3:** **In-process `orphan.NewRunnable.TickOnce()` over kubectl exec.** The orphan-revocation Go code path is identical whether the operator binary or the test binary calls `TickOnce()`. Driving it in-process gives a `bytes.Buffer`-backed audit logger we can parse line-by-line; driving it via the in-cluster operator requires `kubectl logs --since=...` grep with race tolerance against multiple ticks. In-process wins on assertion ergonomics and runtime (~30s vs. ~6min wait for one timer fire).

### Deletions and Makefile

- **D-07-v3:** **`docker-compose.yml` deleted in full.** User answered Q1 on 2026-05-20: prefer kind+Helm as the single substrate. `make dev-up` / `make dev-down` go with it. Host-side `psql` workflows now connect via `kubectl port-forward svc/ach-postgres` (future Makefile `psql` target if a dev surfaces a need; deferred for now).

- **D-08-v3:** **`scripts/e2e-kind.sh` wrapper deleted.** It was a 5-line backward-compat shim to `make e2e-full` after `e1b943c`. No external callers (CI uses `make e2e` directly). Removing reduces drift surface.

- **D-09-v3:** **`internal/orphan/uat_test.go` deleted.** Its `TestSC5LiveOrphanRevocation` body is logically equivalent to (and now subsumed by) `phase2_sc5_orphan_test.go`'s `OrphanReapLive` sub-T. Keeping it would split SC#5 coverage across two build-tag-isolated suites with overlapping assertions.

- **D-10-v3:** **Keep `test-e2e` alias as Kubebuilder convention.** Even though `e2e-full` is the canonical target, `make test-e2e` is what Kubebuilder-scaffolded boilerplate expects; tooling that scrapes the Makefile (gomod-aware IDEs, CI generators) keys on the name.

The stale `make e2e-kind` mention gets a one-line footnote `> Note: superseded by Phase 02.3 — use `make e2e-full`.` Inserted as a separate line, no in-line edit.
