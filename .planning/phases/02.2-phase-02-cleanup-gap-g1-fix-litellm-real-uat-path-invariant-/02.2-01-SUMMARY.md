# Phase 02.2 Plan 01: Fix Gap G1 (`ListUserKeys` endpoint mismatch + namespace translation column + OutcomeRevoked rename) Summary

**One-liner:** Swapped LiteLLM `/key/info?user_id=` → `/key/list?user_id=...&return_full_object=true&include_team_keys=false`, renamed `UserKeyInfo.KeyID` → `Token` (json:`token`), one-shot replaced `OutcomeSuccess` → `OutcomeRevoked` codebase-wide, and shipped migration 000003 adding nullable `litellm_token TEXT` with partial UNIQUE indexes to `personal_keys` and `environment_keys`.

## What Changed

### Wire-format diff (the actual Gap G1 fix)

| Surface | Before (broken on LiteLLM v1.83.10) | After (Phase 02.2 Plan 1) |
|---|---|---|
| Path string | `/key/info?user_id=<id>` (404 not_found_error) | `/key/list?user_id=<id>&return_full_object=true&include_team_keys=false` |
| Error wrap | `litellm: decode GET /key/info: %w` | `litellm: decode GET /key/list: %w` |
| Response field | `key_id` (singular-key namespace) | `token` (LiteLLM-internal opaque hex) |
| `UserKeyInfo` Go field | `KeyID string \`json:"key_id"\`` | `Token string \`json:"token"\`` |

### Outcome enum rename (one-shot, greenfield discipline)

```diff
 const (
-    OutcomeSuccess            = "success"
+    OutcomeRevoked            = "revoked"
     OutcomeLiteLLMUnreachable = "litellm_unreachable"
     OutcomeRevokeFailed       = "revoke_failed"
 )
```

`OutcomeSuccess` is **deleted outright** (WARNING 6 — no dead aliases). `grep -rn 'OutcomeSuccess' internal/` returns zero matches across the entire codebase. Plan 02's `uat-g1.sh` greps the JSON form `'"outcome":"revoked"'` against the operator audit log; the operator emitter is `slog.NewJSONHandler` at `internal/audit/handler.go:45`, so the wire form matches.

### Migration 000003 (the namespace-translation column)

`db/migrations/000003_litellm_token.up.sql`:
- `ALTER TABLE personal_keys ADD COLUMN IF NOT EXISTS litellm_token text;`
- `ALTER TABLE environment_keys ADD COLUMN IF NOT EXISTS litellm_token text;`
- `CREATE UNIQUE INDEX IF NOT EXISTS personal_keys_litellm_token_uniq ON personal_keys (litellm_token) WHERE litellm_token IS NOT NULL;`
- `CREATE UNIQUE INDEX IF NOT EXISTS environment_keys_litellm_token_uniq ON environment_keys (litellm_token) WHERE litellm_token IS NOT NULL;`

`db/migrations/000003_litellm_token.down.sql` drops the two indexes first, then the two columns (explicit ordering for intent; Postgres enforces this natively via cascade).

**No prefix-validation constraint** — LiteLLM hex tokens have no fixed prefix (unlike ACH's `pkid_*` / `ekid_*` CHECK on `key_id` from migration 000001). The header comment documents this and points at Phase 3 SSO as the write path.
