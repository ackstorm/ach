### scripts/uat-g1.sh (new — 264 lines, mode 0755)

Step sequence per CONTEXT D-10:

1. **Stack up** — `$COMPOSE up -d` + wait for ACH `postgres` `pg_isready` (DEADLINE=60s) and LiteLLM `/health/readiness` (DEADLINE=$HEALTH_TIMEOUT_S).
2. **Migrations** — `dev_run ... go run ./cmd/migrate` applies Phase 1 + 2 + 000003.
3. **Seed** — `INSERT INTO personal_keys` with `key_id=pkid_uat_g1`, `litellm_user_id=u-uat-g1`, `litellm_token='placeholder-token-pending-litellm-generate'`.
4. **Generate key** — `POST /key/generate` against LiteLLM under `user_id=u-uat-g1`, captures `key` via `jq -r .key` → `$TOKEN` (jq hard-required at script start).
5. **Update token** — `UPDATE personal_keys SET litellm_token='$TOKEN'` via psql against ACH postgres.
6. **Backdate** — `UPDATE "LiteLLM_VerificationToken" SET created_at=now()-interval '11 minutes' WHERE token='$TOKEN'` via psql against `litellm-db` (defeats 10m `OrphanAgeFloor`).
7. **Launch operator** — `dev_run ... ACH_ORPHAN_CLEANUP_INTERVAL=5m ... go run ./cmd/operator > $OPERATOR_LOG &`, records PID to `$OPERATOR_PID_FILE`.
8. **Sleep** — `sleep 360` (one 5m tick + 1m slack).
9. **Assert (JSON-form grep)** — BLOCKER 1 fix. Audit emitter is `slog.NewJSONHandler` per `internal/audit/handler.go:45`. Primary check:

```bash
if grep -E '"audit":true.*"outcome":"revoked".*"user_id":"u-uat-g1"' "$OPERATOR_LOG" >/dev/null; then
    echo "uat-g1: PASS — revocation audit event observed (ordered match)"
    exit 0
elif awk '/"audit":true/ && /"outcome":"revoked"/ && /"user_id":"u-uat-g1"/' "$OPERATOR_LOG" | grep -q .; then
    echo "uat-g1: PASS — revocation audit event observed (order-independent awk match)"
    exit 0
else
    echo "uat-g1: FAIL — no audit event with audit:true + outcome:revoked + user_id:u-uat-g1 observed"
    echo "uat-g1: last 30 lines of operator log:"
    tail -30 "$OPERATOR_LOG"
    exit 1
fi
```

Hard prereq: `command -v jq >/dev/null 2>&1 || { echo "uat-g1: jq is required..."; exit 2; }` runs immediately after `set -euo pipefail`.

Out of scope per D-11: no strict exactly-one-event audit-stream parsing; no post-revocation `GET /key/info?key=` LiteLLM-side 404 verification.

## Deviations from Plan

### [Rule 3 — Workflow] Task 1 split into two commits (Task 1 + Task 1 fixup)

**Found during:** Task 1 commit step.

**Issue:** The first `git add` command listed both the file-renamed/deleted paths *and* the content-edited paths in a single invocation. Git's `git add` halted with `fatal: pathspec 'docker-compose.spike.yaml' did not match any files` (the file had been pre-staged for deletion by `git rm` so the path no longer exists on disk) — and because the bad path was the second arg, the *first* arg `docker-compose.yml` never got staged either. Commit `4870314` therefore captured only the delete + rename, missing the docker-compose.yml content edits and the litellm-config.yaml header refresh.

**Fix:** Per protocol "never amend, always create a new commit", a follow-up commit `259dbc5` was created with the missed edits and a commit body explaining the lineage. End-state on disk is identical to what a clean single-commit run would have produced.

**Files affected:** docker-compose.yml, scripts/litellm-config.yaml.

**Commits:** `4870314` + `259dbc5` (together close Task 1).
