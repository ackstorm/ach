Base resolver:
```
type liteLLMTeamsResolver struct { ll litellm.Client }

func NewLiteLLMTeamsResolver(ll litellm.Client) (TeamsResolver, error) {
    if ll == nil { return nil, errors.New("keystore: nil litellm client") }
    return &liteLLMTeamsResolver{ll: ll}, nil
}

func (r *liteLLMTeamsResolver) Resolve(ctx context.Context, email string) ([]string, error) {
    info, err := r.ll.UserInfoByEmail(ctx, email)
    if err != nil {
        if errors.Is(err, litellm.ErrNotFound) { return []string{}, nil }
        return nil, err
    }
    if info == nil || len(info.Teams) == 0 { return []string{}, nil }
    return info.Teams, nil
}
```

Cached wrapper:
```
type redisCachedTeamsResolver struct {
    base TeamsResolver
    rdb  *redis.Client
    sf   singleflight.Group
    ttl  time.Duration
}

func NewCachedTeamsResolver(base TeamsResolver, rdb *redis.Client) (TeamsResolver, error) {
    if base == nil { return nil, errors.New("keystore: nil base teams resolver") }
    if rdb == nil  { return nil, errors.New("keystore: nil redis client") }
    return &redisCachedTeamsResolver{base: base, rdb: rdb, ttl: defaultTTL}, nil
}

func (r *redisCachedTeamsResolver) Resolve(ctx context.Context, email string) ([]string, error) {
    key := teamsCacheKeyPrefix + email
    if raw, err := r.rdb.Get(ctx, key).Bytes(); err == nil {
        var teams []string
        if jsonErr := json.Unmarshal(raw, &teams); jsonErr == nil { return teams, nil }
    }
    v, sfErr, _ := r.sf.Do(email, func() (any, error) {
        return r.base.Resolve(ctx, email)
    })
    if sfErr != nil { return nil, sfErr }
    teams, _ := v.([]string)
    if teams == nil { teams = []string{} }
    if b, err := json.Marshal(teams); err == nil {
        _ = r.rdb.Set(ctx, key, b, r.ttl).Err()
    }
    return teams, nil
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Forwarder/Content Service → TeamsResolver | Cached-resolver returns canonical Team-ID list; consumers map list to authorization decisions. |
| TeamsResolver → LiteLLM REST | LiteLLM is trust authority for team membership; ACH does not second-guess. |
| TeamsResolver → Redis | Cache holds non-secret team-ID lists keyed by email (PII-bearing but not credential-bearing). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Spoofing | Cache key collision | mitigate | Cache key is `ach:teams:<email>` — verbatim email per DB-05 (no normalization). Different SSO emails are different cache entries. Phase 3 keystore uses `ach:key:<credential_hash>` — disjoint keyspace prefix, no possible collision. |
| T-04-03-02 | Information disclosure | Redis cache | accept | Team IDs are non-secret (LiteLLM publishes via /user/info to any caller with the master key). Email IS PII; Redis must be RBAC-scoped at the deployment layer (NetworkPolicy + AUTH per Phase 3 D-09). No new mitigation added here. |
| T-04-03-03 | Tampering | Stale team cache after team-removal | accept | 60s TTL bounds staleness; Hub spec accepts this window. Forced invalidation on team-removal is out of v1alpha1 scope (v1beta1 §20 backlog: "auto-revoke ek_ on Team-membership removal"). |
| T-04-03-04 | Denial of service | LiteLLM-unreachable storm | mitigate | singleflight dedup ensures cache-miss for the same email collapses to one upstream call. Test T10 verifies. Forwarder maps error to 503 litellm_unreachable per FWD-03; deployment-layer retry/backoff at CLI side. |
| T-04-03-05 | Spoofing | Empty-team-list confusion | mitigate | Empty-slice IS cached (Test T7) — `[]string{}` is a valid LiteLLM answer ("user has no teams"). Distinguished from "cache miss" via Redis key presence, not value content. |
| T-04-03-SC | Tampering | go module install | mitigate | No new go.mod entries. Singleflight and go-redis/redis/v9 are already direct deps from Phase 3 (legitimate, widely-deployed). |

</threat_model>
