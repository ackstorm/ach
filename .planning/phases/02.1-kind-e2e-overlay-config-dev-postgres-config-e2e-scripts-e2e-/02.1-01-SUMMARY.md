## Documented deviations from PLAN.md

1. **Task 5a was inserted as a pre-Task-5 step.** The plan's mandated hermetic Option B path (in-cluster nginx serving HTTP) was blocked by (a) the `^https://` CRD admission pattern on `HTTPSource.URL` and (b) the runtime guard at `internal/sources/http/fetcher.go:65`. After confirming with the user, the HTTPS-only invariant (T-02-02-03) was lifted across all three layers. Production deployments are now expected to use https:// URLs **by convention** instead of by machine enforcement.

2. **Anonymous SCM fetch support added (Task 5b).** The plan's `plugin_github_basic.yaml` fixture mandated `type: github` against a public repo. The github fetcher previously required a non-empty PAT (`internal/sources/github/fetcher.go:79`) and the CRD made `AuthSecretRef` `+kubebuilder:validation:Required`. After the user's directive that "anonimo is a must" for github/gitlab/bitbucket, Task 5b dropped the requirement at all three layers: types (pointer field, optional), three fetchers (build SDK client without token, omit auth headers when nil), and the controller's `extractAuthSecretRef`. The SC1 fixture now uses `type: github` against `octocat/Hello-World @ master` with NO `authSecretRef` and the operator successfully fetches the public repo tarball anonymously. S3/GCS retain mandatory auth (no anonymous mode in v1alpha1).

3. **e2e overlay patches the credential-hash pepper Secret.** Plan did not anticipate that the operator's `pepperenv.Load` (cmd/operator/main.go:139) refuses to start when the Plan 08 placeholder value is still in place. Task 7 added Patch 3 to `config/e2e/kustomization.yaml`.

4. **Phase 2 test verification moved from kubectl exec to status.storageLocation.** Plan's `kubectl exec ... stat/ls/sh` strategy assumed a regular Linux operator image; in reality the operator runs from a distroless base (no shell, no coreutils). Switched to reading status.storageLocation off the CR — this is the contractually-defined observable: the reconciler only writes a non-empty path after rename(2) succeeds.

5. **Removed the probeFixtureServer step.** `kubectl run --rm -i` for a debug Pod hung past 60s in the smoke run despite the fixture-server itself being healthy (200 OK on every probe). The fixture-server's own readinessProbe is verified via `kubectl rollout status` in `applyFixtureServer`, making the additional probe redundant.

6. **Phase 1 SC#3 (Environment finalizer drain) skips under e2e-kind.** The plan's claim that the overlay "does not break the Phase 1 invariants" was incorrect: SC#3 calls `kubectl delete environment example --wait=true` whose drain depends on a reachable LiteLLM. The e2e overlay deliberately points the operator at an unreachable endpoint. SC#3 is preserved for the `make test-e2e` path (no overlay) and skipped under E2E_SKIP_SETUP=1.

7. **`make docker-build` does not accept `IMG=...` override.** The plan assumed sister-project parity; ACH's Makefile hardcodes `:latest` for all 5 images. The orchestrator now builds all 5 at `:latest` then retags `ach-operator:latest` → `ach-operator:e2e`.
