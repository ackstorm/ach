Phase 02.1 closes this gap by shipping THREE small assets:

1. **`config/dev-postgres/` kustomize component** — a development-only Postgres Deployment + Service + PVC (≤ 100 LOC of YAML) that the e2e overlay pulls in. Service name `ach-postgres`; namespace `system` (rewritten to `ach-system` by kustomize). Labels `app=postgres` so the existing `findPostgresPod` helper resolves it. Image `postgres:16-alpine` (matches `docker-compose.yml` and `docker-compose.spike.yaml`). The PVC is `emptyDir`-equivalent (no real persistence claim; ephemeral for kind).
2. **`config/e2e/` kustomize overlay** — mirrors sister `../ach_litellm/config/e2e/kustomization.yaml`: pulls in `../default` + `../dev-postgres`, sets `images: [{name: controller, newName: ach-operator, newTag: e2e}]`, patches operator Deployment with `replicas: 1`, leader-election off, namespace `ach-system`. Also patches the existing `ach-db-url` Secret URL to `postgres://ach:ach@ach-postgres.ach-system.svc.cluster.local:5432/ach?sslmode=disable` (the existing literal `.system.` in the Secret is a Phase 1 dead-letter — see Decisions D-02).
3. **`scripts/e2e-kind.sh` orchestrator** — mirrors sister `../ach_litellm/scripts/e2e-kind.sh`: 7-step lifecycle (create cluster → docker-build manager → kind-load → `make install` CRDs → `kustomize build config/e2e | kubectl apply -f -` → wait Deployment rollout → `go test -tags=e2e ./test/e2e/...`) with `E2E_KEEP_CLUSTER=1` debug-keep escape hatch and trap-based cleanup on EXIT. Plus a Makefile target `e2e-kind` that invokes it.

Then the deliverable is *exercising* Phase 02 SC#1–4 from the live cluster. The Plan 01-11 e2e suite covers Phase 1 invariants only; this phase adds Phase 02 invariant tests in `test/e2e/phase2_invariants_test.go` (single file; one TestPhase2Invariants harness covering SC#1 plugin publish, SC#2 marketplace three-stage, SC#3 alphabetical conflict, SC#4 size-cap).

Phase 02.1 explicitly **excludes**: any code change to the operator, fetchers, reconcilers, or db layer (already verified by envtest); the Plan 02 G1 fix for `ListUserKeys` endpoint mismatch (deferred to Phase 3 per `02-HUMAN-UAT.md` Gaps section); GitHub Actions CI integration (the orchestrator runs locally only); the long-running marketplace stress scenarios (single-CR-per-source-type smoke is enough for SC validation).

<decisions>
## Implementation Decisions

### Scope shape

- **D-01:** Single-plan phase. The work fans naturally into three asset deliverables but they share the same author context (kustomize/YAML/shell), have no inter-asset dependencies (the overlay references the component, but the dev-postgres asset is read-only), and the live test file shipped together with the manifests *needs them* to compile correctly. Splitting into multiple plans creates more orchestration overhead than the assets themselves.

### Kustomize layout

- **D-02:** **Fix the `ach-db-url` Secret URL** in the e2e overlay via a kustomize JSON patch, not by editing `config/secrets/db_url_secret.yaml` directly. The Phase 1 secret value `postgres://ach:ach@ach-postgres.system.svc.cluster.local:5432/ach?sslmode=disable` references namespace `system`, but `config/default/kustomization.yaml` sets `namespace: ach-system` which rewrites only `metadata.namespace` — Secret string-data is opaque. The e2e overlay patches the Secret URL to `.ach-system.svc.cluster.local` to match the actual rendered namespace. Phase 1 deferred this because it shipped no live Postgres; Phase 02.1 inherits the responsibility. The Phase 1 value stays as-is (does not get rewritten) so Phase 1 e2e tests continue to fail-soft on DB connectivity if they ever depended on the literal URL — but they don't (they use testcontainers).
- **D-03:** **`config/dev-postgres/` is a kustomize *component* (`kind: Kustomization` with `components:`-discoverable resources)**, not a base/overlay. This signals "opt-in development dependency, do not ship to production." The `config/e2e/kustomization.yaml` pulls it in via `resources: [../default, ../dev-postgres]`. Production Helm chart (Phase 7) explicitly will not reference `dev-postgres`.
- **D-04:** **Postgres image is `postgres:16-alpine`** matching `docker-compose.yml` (Phase 1) and `docker-compose.spike.yaml` (Phase 02 SC#5 UAT). No version-probe / version-gate logic — engineer picks the version manually ([[feedback_litellm_version_control]] pattern). Single-replica Deployment with `strategy: Recreate`. Env: `POSTGRES_DB=ach`, `POSTGRES_USER=ach`, `POSTGRES_PASSWORD=ach` (matches the Secret value). PVC is `emptyDir` (no PersistentVolumeClaim) — kind clusters are ephemeral, the e2e cycle creates and destroys the cluster, so persistence is harmful.

### Orchestrator shape

- **D-05:** **Mirror sister `../ach_litellm/scripts/e2e-kind.sh` verbatim** for the 7-step lifecycle. Differences: cluster name `ach-operator-e2e` (not `workspace-operator-e2e`); image tag `ach-operator:e2e`; kustomize overlay path `config/e2e`; the test invocation is `go test -tags=e2e ./test/e2e/...` (already wired by Plan 01-11 Makefile target). Trap-based cleanup. `E2E_KEEP_CLUSTER=1` keeps the cluster up for `kubectl` poking.
- **D-06:** **Dual invocation path** — the script must work both inside the devtools container (via `./scripts/dev.sh make e2e-kind`) AND on the host directly (the user has `kind` on PATH per the most recent host check). The container path stays preferred for reproducibility; the host path is a debugging escape hatch. Both paths chdir to `${REPO_ROOT}` and use bare tool names — the devtools image and the host both expose `kind`, `kubectl`, `kustomize`, `docker`, `go`.
- **D-07:** **`scripts/e2e-kind.sh --cleanup`** is a no-op pass-through that calls `kind delete cluster --name ach-operator-e2e` and exits. Distinct from the trap-on-EXIT cleanup which is in-band.

### Test discipline

- **D-08:** **One new test file** — `test/e2e/phase2_invariants_test.go` with a `TestPhase2Invariants` parent harness and four subtests `t.Run("SC1_PluginPublish", …)` … `t.Run("SC4_SizeCap", …)`. Build-tag `e2e` (matches `phase1_invariants_test.go`). Reuses the existing `e2e_suite_test.go` infrastructure (envconfig, RESTMapper, dynamic client). Test bodies are minimal — they verify the *observable contract* (a CR is reconciled, a file appears on the PVC, a Condition flips), NOT the implementation. SC#5 stays on the compose harness (already verified) and is NOT replicated as a kind test (would require pulling in a LiteLLM Pod, which is out of scope).
- **D-09:** **No envtest changes.** The existing envtest suite covers reconciler-level invariants; this phase adds *integration*-level live-cluster verification. The two test surfaces are complementary; envtest does NOT become flaky/redundant.

### Makefile + naming

- **D-10:** **New Makefile target `e2e-kind`** with help-text discipline matching existing targets (`## scripts/e2e-kind.sh wrapper — full lifecycle (create cluster → build → load → apply → test → cleanup). E2E_KEEP_CLUSTER=1 to keep cluster.`). The existing `test-e2e` target stays — it runs `go test -tags=e2e` against an already-running cluster; `e2e-kind` is the wrapper that brings the cluster up first.
- **D-11:** **Kind cluster name `ach-operator-e2e`** (mirrors sister naming). Image tag `ach-operator:e2e` (matches kustomize image override).

<specifics>
## Success Criteria — Phase 02.1

1. **`make e2e-kind` exits 0** on a clean machine that has Docker + `kind` available. The lifecycle: creates kind cluster `ach-operator-e2e`, builds `ach-operator:e2e`, kind-loads, applies CRDs via `make install`, renders `config/e2e` overlay, applies it, waits for the operator Deployment rollout (≤ 120s), and runs `go test -tags=e2e ./test/e2e/...` — the existing Phase 1 invariants suite + the new Phase 2 invariants suite both pass.
2. **`findPostgresPod` resolves a real Pod** in the operator namespace via label `app=postgres` (or the alt labels it already probes), and the operator's `ach-db-url` Secret resolves DNS to that Pod's Service. Operator container reaches Ready (which currently fails because of DB unreachability — this phase makes it Ready for the first time in a live cluster).
3. **Phase 02 SC#1 is exercisable live**: `kubectl apply` of a fixture `Plugin` CR with `type: github` and a public repo URL produces a `plugin/<name>.tar.gz` file on the operator's PVC within one reconcile interval. The new test asserts the file exists by `kubectl exec`-ing into the operator Pod (or reading via a side-car if PVC ReadWriteOnce blocks that — fall back to a Status condition assertion).
4. **Phase 02 SC#2/SC#3 are exercisable live**: two `PluginMarketplace` CRs with overlapping plugin names — alphabetical winner gets `Synced=True`, loser gets `Synced=False reason=NameConflict`. Test reads Conditions, not files. Uses a real Claude-Code-shaped fixture file hosted at a stable public URL (or shipped in `test/e2e/fixtures/` and served via a `kubectl proxy`-style sidecar — implementation detail for the planner).
5. **Phase 02 SC#4 is exercisable live**: a `Plugin` CR pointing at a real >50 MiB archive (or with `ACH_PLUGIN_MAX_SIZE_MIB=0` env override on the operator Pod) flips `SourceReachable=False reason=PluginTooLarge`. The `0` env path is easier to test deterministically — test patches the operator Deployment env, waits for new Pod, applies a Plugin CR, asserts the Condition.
6. **`scripts/e2e-kind.sh --cleanup`** deletes the cluster and any orphaned docker artifacts (image tag `ach-operator:e2e`). Idempotent: succeeds when cluster is absent.

</specifics>
