<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application→Postgres | DB-03/04: HMAC-SHA-256 hashes (computed application-side with the env-var-sourced pepper) cross this boundary as `credential_hash`. Plaintext bearer keys MUST NEVER cross it. |
| migration tool→DB | The migration init container (Plan 08) is the SOLE writer of schema. Application code never runs DDL. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | plaintext key persisted to DB | mitigate | Schema has zero columns that could hold plaintext (no `credential_plaintext`, `bearer_token`, etc.). Acceptance criterion asserts `grep -v` of these patterns returns no matches. The DB-03 contract (plaintext hashed before insert; never reversibly stored) is enforced by Plan 04 (`internal/credhash`) and Phase 3 row-writing code. |
| T-03-02 | Tampering | application-side INSERT with mismatched key prefix | mitigate | CHECK constraints `personal_keys_key_id_prefix` and `environment_keys_key_id_prefix` reject any `key_id` lacking the canonical prefix. Integration test asserts a CHECK-violation error code (`23514`). |
| T-03-03 | Repudiation | duplicate `credential_hash` masking a bearer collision | mitigate | UNIQUE constraint on `credential_hash` makes a hash collision an INSERT failure rather than a silent override. Integration test asserts `23505`. |
| T-03-04 | Tampering (migration) | adversarial migration file injection | mitigate | Migration files live in the repo, are reviewed at commit time, and ship into the Operator container image (Plan 10). The migration init container (Plan 08) runs the SAME migrate binary against the SAME embedded files — no runtime fetch. D-08 forbids best-effort semantics: failed migration → Pod stays in `Init:Error`. |
| T-03-05 | Information Disclosure | Postgres connection string leaked via logs | mitigate | `internal/db.Open` accepts the URL as a function argument; it is never logged. The caller (Plan 06's operator main) sources from env `ACH_DB_URL` and never echoes it. Plan 08's `manager.yaml` mounts the URL from a Kubernetes Secret. |
| T-03-06 | Denial of Service | unbounded `pgxpool.MaxConns` | accept | `MaxConns: 10` is a sane default for the Operator's reconciler. Phase 3's Platform API may override; Phase-1 risk is negligible. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No npm/pip/cargo installs. Go modules only (`pgx/v5`, `golang-migrate/migrate/v4`, `testcontainers-go`); all three are widely-deployed `[KNOWN]` packages — no `[ASSUMED]`/`[SUS]` checkpoint required. |
</threat_model>
