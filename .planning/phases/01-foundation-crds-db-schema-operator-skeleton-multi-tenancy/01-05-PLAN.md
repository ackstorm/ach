<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| K8s API server→controller | Controllers consume CRs via the informer cache; CEL admission (Plan 02) is the upstream filter. |
| controller→PVC | External-ref controllers issue `os.Remove`/`os.RemoveAll` against the PVC mount under `/var/cache/ach`. Path-traversal must not escape the mount. |
| controller→LiteLLM | Phase 1 routes through NoopClient. Phase 2 replaces with real REST traffic — until then no LiteLLM traffic exists. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | external-ref controller path-traversal via malicious CR name | mitigate | `cr.Name` is K8s-validated as a DNS-1123 label (alphanumerics + `-`, no `..`, no `/`). Acceptance criterion confirms `filepath.Join` with `r.CacheRoot` as the first segment so a malicious name like `../etc` would resolve under `<CacheRoot>/plugin/..` — still safe because `filepath.Clean` strips traversal and K8s admission rejects the dot characters at validation. Defense in depth: Plan 11's envtest asserts that a CR with `..` in name fails admission. |
| T-05-02 | Tampering | finalizer removed BEFORE drain completes (lost ek_ row) | mitigate | Reconcile body sequences `DeleteAccessGroup → DeleteTag → ek_ drain → RemoveFinalizer`. Acceptance criterion asserts the textual order via `grep -n`. Any return-with-error before RemoveFinalizer keeps the finalizer in place and retries. |
| T-05-03 | Repudiation | NoopClient silently swallowing real LiteLLM failures | accept (Phase 1) | NoopClient always returns nil. Phase 2 introduces real RestClient that returns errors; the same call sites then propagate them. Phase 1 has no LiteLLM connectivity to defraud. |
| T-05-04 | Tampering | Phase 2 swap accidentally types reconciler against `*RestClient` (concrete) instead of `Client` (interface) | mitigate | Compile-time assertion `var _ Client = (*NoopClient)(nil)` + interface-typed struct field. Plan 11's grep gate asserts the literal pattern `LiteLLM\s+litellm\.Client`. |
| T-05-05 | Denial of Service | infinite loop in ek_ drain polling | mitigate | Loop cap of 10 iterations; on every iteration `UPDATE ... WHERE status='active'` is idempotent. Phase 1 has zero rows so first SELECT returns 0 and loop exits. Phase 3+ may revisit when rows exist. |
| T-05-06 | Information Disclosure | log lines from NoopClient leaking sensitive Environment names | accept | Environment names are non-sensitive (K8s metadata.name). Acceptable per Hub §18.2 audit conventions. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No npm/pip/cargo installs. Go modules only (`logr` already transitive from kubebuilder; `pgx/v5` from Plan 03). |
