<feature>
  <name>credhash — HMAC-SHA-256 credential hashing</name>
  <files>internal/credhash/credhash.go, internal/credhash/credhash_test.go, internal/credhash/doc.go</files>
  <behavior>
    Behavioral cases (each becomes a test in `credhash_test.go`):
    1. `Hash(pepper, plaintext)` returns a hex-encoded 64-char digest (32 bytes × 2) for any non-empty pepper.
    2. `Hash(pepper, "pk_abc")` produces the SAME hex digest on every call with the same inputs (determinism).
    3. `Hash(pepperA, "pk_abc") != Hash(pepperB, "pk_abc")` when `pepperA != pepperB` (pepper affects digest).
    4. `Hash(pepper, "pk_abc") != Hash(pepper, "pk_abd")` (plaintext affects digest).
    5. `Hash(nil, "anything")` returns `("", ErrEmptyPepper)`.
    6. `Hash([]byte{}, "anything")` returns `("", ErrEmptyPepper)`.
    7. `Equal(h, h)` returns true for any well-formed hex string `h`.
    8. `Equal(h1, h2)` returns false for distinct well-formed hex strings.
    9. `Equal("xx", "yy")` (malformed hex) returns false WITHOUT panic.
    10. `Equal("", "")` returns true (degenerate but not a panic).
    11. Race test: 1000 concurrent goroutines each calling `Hash` with the same pepper+plaintext — all produce identical output (proves no shared mutable state).
  </behavior>
  <implementation>
    Stdlib-only. Imports: `crypto/hmac`, `crypto/sha256`, `crypto/subtle`, `encoding/hex`, `errors`. NO third-party deps. NO logger imports (DB-04 — never log plaintext).

    `credhash.go` per PATTERNS.md lines 575-609 (lift verbatim, add the doc.go separately for `go doc` discoverability).

    Signature contracts:
    ```

    func Hash(pepper, plaintext []byte) (string, error)
    func Equal(a, b string) bool
    ```

    `doc.go` content: 5-10 line package comment citing Hub §16.1 + D-09 + D-10, explaining that the pepper is sourced from `ACH_CREDENTIAL_HASH_PEPPER` env var (mounted from the `ach-credential-hash-pepper` Secret per Plan 09), and that this package NEVER reads env vars or logs — callers pass the pepper as an argument.
  </implementation>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller→credhash | Plaintext bearer keys (`pk_…`, `ek_…`) enter `Hash` as the `plaintext []byte` parameter. After return, the caller MUST zero or discard the plaintext; this package does not retain or log it. |
| K8s Secret→Pod env | The pepper enters the Pod via `ACH_CREDENTIAL_HASH_PEPPER` (Plan 09 mounts the Secret). credhash itself never reads env vars. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | plaintext key leak via log statement | mitigate | Acceptance criterion asserts `grep -E '\blog\.|slog\.|fmt\.Print|os\.Std' internal/credhash/credhash.go` returns zero matches. doc.go states the discipline. |
| T-04-02 | Tampering | timing-attack hash comparison | mitigate | `Equal` uses `crypto/subtle.ConstantTimeCompare` (not `==`). Test asserts the call is wired (compile-time presence of `subtle` import + behavioral test). |
| T-04-03 | Spoofing | hash collision allowing key impersonation | accept | HMAC-SHA-256 collision resistance is the industry-standard ASVS L1 acceptable primitive per Hub §16.1. Pepper rotation deferred to v1beta1 (CONTEXT D-10). |
| T-04-04 | Information Disclosure | hash compare panicking on adversarial hex input | mitigate | `Equal` decodes BOTH inputs first; returns false on ANY decode error. Test `TestEqualMalformedHexFalseNoPanic` asserts this with `defer recover()`. |
| T-04-05 | Tampering | empty-pepper bypass producing a deterministic zero-pepper digest | mitigate | Defensive `len(pepper) == 0` check returns `ErrEmptyPepper`; Plan 06's operator main aborts process startup when `ACH_CREDENTIAL_HASH_PEPPER` is unset. Two layers of defense. |
