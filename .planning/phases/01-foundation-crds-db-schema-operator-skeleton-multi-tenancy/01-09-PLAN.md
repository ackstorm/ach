       # Insert `namespace: system` under `metadata:` if not already present.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ServiceAccount→K8s API server | Each component's SA presents a token; kube-apiserver authorizes via the RoleBinding. RBAC is the trust boundary preventing cross-component CR mutation. |
| Namespace edge | Namespace-scoped Role + RoleBinding (MULTI-01) prevents the Operator's SA from seeing CRs in adjacent ACH deployments running in other namespaces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Elevation of Privilege | Platform API SA writes Environment status | mitigate | Platform API Role has NO write verbs on `environments` (only get/list/watch). Patch carve-out is restricted to four external-reference kinds. Plan 11's e2e test asserts `kubectl auth can-i patch environments.ach.ackstorm.ai --as=system:serviceaccount:ach-system:ach-platform-api` returns `no`. |
| T-09-02 | Elevation of Privilege | Forwarder SA reads cached file contents via API | mitigate | Forwarder Role grants NO access to `plugins`/`prompts`/`artifacts`/`pluginmarketplaces` — only `environments` + `backendidentitypolicies`. Cache files live on PVC, not API; this RBAC posture closes the API-side leak. |
| T-09-03 | Elevation of Privilege | Operator SA escalates to ClusterRole | mitigate | The Role is namespace-scoped; even if the Operator binary is compromised, its token only authorizes within `ach-system`. MULTI-01 prohibits ClusterRole/Binding (acceptance criterion asserts via grep). |
| T-09-04 | Tampering | RoleBinding accidentally points to wrong SA | mitigate | Acceptance criteria assert each RoleBinding's `subjects.name` matches the SA name in the sibling file. Plan 11's e2e test runs `kubectl auth can-i ... --as=` for each SA and asserts the expected verb set. |
| T-09-05 | Spoofing | rogue Pod in same namespace impersonates ACH SA token | mitigate | Out of scope for RBAC — K8s ServiceAccount projection ensures only Pods with the SA bound get its token. PodSecurityStandards/restricted (Plan 08) prevents arbitrary token mounts. |
| T-09-06 | Information Disclosure | leader-election ConfigMap leak | accept | Leader election is OFF in Phase 1 (single-replica Recreate). Plan 09 does NOT ship the leader-election Role. |
| T-09-07 | Tampering | controller-gen output drifts from manual edits | mitigate | `make manifests` regenerates `config/rbac/role.yaml` from `+kubebuilder:rbac:` markers; Task 1 extracts into `operator_role.yaml` once. Discipline: `make manifests` output goes to `role.yaml` (kubebuilder-generated, then deleted/ignored); `operator_role.yaml` is the hand-curated Role-kind version. Document this in the SUMMARY. |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No npm/pip/cargo installs. YAML manifests only. |
</threat_model>
