<objective>
Close CR-02 (root cause of the Phase 7 verification failure): wire the constructed Extractor + AdapterDispatcher into the orchestrator so steps 7–10 of the §6.7 14-step commit sequence actually execute. The W3-05 plan built `wiring.go` with substantive `extractorImpl` (104+ LOC) and `adapterDispatcherImpl` (90+ LOC), AND built `NewWiring(...)` to return them as the public `Extractor` + `AdapterDispatcher` interfaces — BUT three gaps prevent the impls from reaching the commit struct:

1. `hydrate.Opts` (`internal/cli/hydrate/flags.go`) has no fields through which the cobra layer can inject these impls.
2. `cmd/ach-cli/cmd/hydrate.go:502` calls `_, _ = hydrate.NewWiring(...)` — both return values discarded.
3. `internal/cli/hydrate/commit.go:240-253` only executes `_ = c.extractor` / `_ = c.adapter` — even with non-nil fields, neither `ExtractContent()` nor `Render()` is invoked.

Additionally `step6Diff`'s output is dead: `_ = diffTargets // W1: not consumed further; W2 wires.` at commit.go:230. The scope-filtered content-target slice never reaches the extraction loop.

Step 11 (STATE-05 inverse-merge / D-16 deepest-first deletion) is also dead in W1: `c.maybeKill(11)` fires at the step boundary but the package-level `hydrate.Sync(prev, newFile, achDir, opts)` (200+ LOC in wiring.go) is never invoked from the orchestrator. STATE-05 is verified at the code level but not wired — a `--sync` invocation today is a no-op on state-entry pruning.

The fix is mechanical and narrow — no new types, no signature changes on `Extractor` / `AdapterDispatcher` / `Sync` (all already correct), no changes to `wiring.go` (the impls are production-quality). This plan does:

- Add two interface-typed fields to `Opts`.
- Populate them in `newCommit()`.
- Capture them in `runHydrateEngine` and thread them into the Opts literal.
- Replace the stub blocks in `run()` with the real per-diffTarget extraction loop + the adapter Render call.
- Invoke `hydrate.Sync(...)` at step 11 (after Render, before step12WriteState) when `c.opts.Sync && !c.opts.DryRun`; accumulate SyncStats into Result.
- Populate `Result.FilesWritten` + `Result.DroppedComponents` + `Result.PlatformID` + `Result.FilesPruned` + `Result.FilesPreserved` from the return values.

Purpose: turn the engine from "ships zero content despite all infrastructure being correct" into "ships real platform configs for all four adapters AND honors --sync inverse-merge." This is the load-bearing fix for the Phase 7 goal — without it, ADAPT-03..07 + STATE-08 + STATE-05 cannot pass at runtime.

Output: 3 source files modified + 1 test file extended. No new packages, no new dependencies. ~55 LOC of additions/replacements, ~5 LOC deletion (the stub blocks).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cobra layer → hydrate.Run | The cobra layer resolves `achDir`, `opts.Platform`, `opts.Bearer`, and constructs Extractor + AdapterDispatcher via NewWiring; Run consumes them as data. |
| Run → extractor / adapter / Sync | Run drives external I/O (HTTP fetch, tar extract, atomic writes, recursive delete-with-warning) through these seams — every call site adds attack surface. |
| local user → workspace filesystem | The engine writes files under `<ach-dir>`; --force can suppress drift refusal. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-W5-01-01 | Tampering | confused-deputy on `c.achDir` passed to ExtractContent / Render / Sync | mitigate | Reuse the existing `state.ResolvePath`-derived `c.achDir` already validated at step 1; do not recompute. SAFE-01 path-traversal defenses in tar.go fire at the extractor boundary. |
| T-07-W5-01-02 | Information Disclosure | `Result.PlatformID` populated from untrusted `opts.Platform` (log-spoofing via embedded newlines) | mitigate | The adapter registry's `Lookup` canonicalizes IDs at Register-time; assigning `result.PlatformID = c.opts.Platform` reflects the caller-supplied value, but the value is only re-used in --verbose stderr where the user is the same caller. Accept residual log-spoofing risk for own-process stderr; document. |
| T-07-W5-01-03 | Denial of Service | `--dry-run` bypass — engine still writes files because Extract/Render/Sync are unconditionally invoked | mitigate | Wrap each of the three new call sites (`c.extractor.ExtractContent`, `c.adapter.Render`, `hydrate.Sync`) in `if !c.opts.DryRun { ... }`. Test `TestRun_DryRun_SkipsExtractorAndAdapter` asserts zero invocations under DryRun. |
| T-07-W5-01-04 | Tampering | `hydrate.Sync` deletes state-entry files; an attacker who can inject entries into the prior `existingState` could trigger overwrite of unrelated paths | accept | `existingState` is read from `state.json` under `<ach-dir>` via `state.Load` — the same trust boundary as the rest of the engine. Sync respects the drift-wins gate (`opts.Force == false && current hash differs from entry.Hash → preserve`). |
| T-07-W5-01-05 | Repudiation | step 11 Sync runs BEFORE step 12 (state.json atomic write); a crash between Sync and step 12 leaves on-disk state out of sync with state.json | accept | Same posture as the existing step 11/12 ordering documented in §6.7 — atomicity-of-state is bounded at step 12; pre-12 disk mutations may be partially observable. sc2_commit_sequence_sigkill exercises this; STATE-05 is documented as "may leave inverse-merged files without a corresponding state.json update if SIGKILL fires between 11 and 12 — resume from clean reads the prior state.json which still references the deleted entries, and the next reconcile prunes them via step 4". |
