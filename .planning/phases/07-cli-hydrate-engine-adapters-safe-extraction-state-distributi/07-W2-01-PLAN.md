<objective>
Ship `internal/cli/extract/` — the safe tar policy + gzip stream + bomb defense layer. SAFE-01 (path/symlink/hardlink/device/FIFO/socket/pax rejection), SAFE-02 (mode masking), SAFE-03 (bomb caps via env vars), SAFE-06 (streaming gzip — no full-buffer).

Staging + autoclaim live in adjacent plans (07-W2-02 + 07-W2-03). This plan owns the load-bearing tar safety contract — the most security-critical surface in Phase 7. CLAUDE.md "Common failure modes" §"Decompression-bomb caps" applies: count uncompressed bytes per-entry AS the bytes stream, NOT after.

Purpose: Decoupled package boundary. tar.go is pure: takes (gzReader, dst, kind, limits, allowSymlinks) and produces a stream of safely-extracted files into dst. Limits parsing is separated into limits.go for testability. Bomb defense is structurally enforced (cannot be bypassed by malicious archives).

  <behavior>
    - Extract(ctx context.Context, gzReader io.Reader, dst string, kind ResourceKind, limits Limits, allowSymlinks bool) (Result, error) where Result holds WrittenFiles []FileWrite (each FileWrite = {RelPath string, Hash string, Mode os.FileMode}) and BytesWritten int64
    - Flow: gz := gzip.NewReader(gzReader); tr := tar.NewReader(gz); for { hdr, err := tr.Next(); if io.EOF break; if err return wrapped; entriesSeen++; if entriesSeen > limits.MaxEntries return ErrTooManyEntries; switch hdr.Typeflag { ... }; ... }
    - Unconditional reject (return ErrUnsafeTarEntry wrapping a descriptive cause) for:
      - hdr.Typeflag == TypeLink (hardlink — even in-tree)
      - hdr.Typeflag == TypeChar / TypeBlock (devices)
      - hdr.Typeflag == TypeFifo
      - hdr.Typeflag == TypeXHeader / TypeXGlobalHeader where the pax extended header attempts a path that fails the same path-safety check (pax path injection)
      - hdr.Typeflag IN any other non-{TypeReg,TypeDir,TypeSymlink} value (sockets etc.)
    - Path safety check (apply to hdr.Name AND to any pax-extended-header path):
      - strings.HasPrefix(name, "/") → ErrUnsafeTarEntry (absolute)
      - filepath.IsAbs(name) on Windows → ErrUnsafeTarEntry (defense in depth)
      - Cleaned := filepath.Clean(name); if strings.HasPrefix(Cleaned, "..") OR Cleaned == ".." OR strings.Contains(Cleaned, "/../") → ErrUnsafeTarEntry (dotdot)
      - resolved := filepath.Join(dst, Cleaned); if !strings.HasPrefix(resolved, dst+string(os.PathSeparator)) → ErrUnsafeTarEntry (escape)
    - Symlink handling:
      - if !allowSymlinks AND Typeflag == TypeSymlink → ErrUnsafeTarEntry (default reject per SAFE-01)
      - if allowSymlinks AND Typeflag == TypeSymlink → resolve hdr.Linkname; reject if it points outside dst (absolute target, or relative target that resolves outside via filepath.Clean check); accept only if the resolved target is within dst
    - Mode masking (TypeReg): mode := os.FileMode(hdr.Mode & 0o0755); strip setuid/setgid/sticky/group-write/world-write — these bits are unset by `& 0o0755`; create the file with O_RDWR|O_CREATE|O_EXCL|O_TRUNC (O_EXCL to refuse claim-stomp; the staging dir is fresh so existing-file is a malicious tar trying to clobber)
    - Mode masking (TypeDir): mode := os.FileMode(0o0755) — forced regardless of hdr.Mode
    - Mtime/atime NOT preserved — do NOT call os.Chtimes
    - Per-entry byte counter: written := int64(0); via io.CopyN in a loop OR via a limitedWriter wrapper that errors when written + n > kind's cap. PREFERRED: read each byte via io.CopyN with the maximum cap as the limit, then check if more bytes follow — if so, return ErrBombCapExceeded. The check fires BEFORE writing the offending bytes when implemented via a limited reader OR before the io.Copy completes when implemented via io.LimitReader + a follow-up tr.Next check. Specific implementation: use io.CopyBuffer with a small (32KB) buffer that accumulates `written` per loop iteration; check `if written + int64(n) > maxBytes { return ErrBombCapExceeded }` before writing the buffered bytes. The CONTEXT.md `<specifics>` 'Bomb defense ordering' constraint MUST be observable in the test (assert no bytes written when the cap is tripped mid-file).
    - On any error during a write, the partially-written file is os.Remove'd and ErrBombCapExceeded (or ErrUnsafeTarEntry) returned; the caller (07-W2-02 staging) discards the entire staging dir per SAFE-03 ("partial output discarded")
