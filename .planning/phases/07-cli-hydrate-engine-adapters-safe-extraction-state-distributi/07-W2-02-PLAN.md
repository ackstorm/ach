<objective>
Ship `internal/cli/extract/stage.go` + `internal/cli/extract/fetch.go` — the per-resource staging + atomic publication layer (SAFE-05) and the content fetch wrapper. Wraps tar.go from 07-W2-01.

Per spec §6.4 + SAFE-05 + STATE-11 / D-15: every resource is extracted/written into `<achDir>/tmp/<rand>/<resource>/` first, then atomically renamed to its final location. Crash mid-stage leaves a discardable tmp dir; the orchestrator (07-W1-06 step 2) sweeps it on next hydrate. The sha256 short-circuit (D-15) lives here: after fetching the response body, compute sha256; compare to the existing final file's sha256 if it exists; if equal, skip the rename + report Skipped (this is the disk-write short-circuit per D-15 — `disk-write step is short-circuited only when freshly-downloaded sha256 matches on-disk sha256`; the fetch itself is unconditional).

Per D-11: tar/gzip handling uses stdlib `archive/tar` + `compress/gzip` only (no third-party tar). The safety policy implemented in 07-W2-01 is invoked through this layer.

Per D-12: SAFE-06 + SAFE-03 size caps (ACH_MAX_EXTRACTED_PLUGIN_MIB / ACH_MAX_EXTRACTED_ARTIFACT_MIB / ACH_MAX_ARCHIVE_ENTRIES) are read once upstream in 07-W2-01 and passed in via the Limits parameter — this layer is cap-aware via tar.Extract.

Per D-14: dual-hash discipline. PublishResult carries BOTH xxh3 hashes (Hash = on-disk bytes; SourceHash = upstream source bytes) for state.json v2 per STATE-02. The sha256 computation is transient — used ONLY for the D-15 disk-write short-circuit comparison; never persisted to state.

Purpose: Per-resource lifecycle isolation. The orchestrator hands StageAndPublish the (kind, downloadURL, finalRelPath, allowSymlinks, limits) — gets back a PublishResult with hash, sourceHash, and any per-resource error. Crashes are bounded to the per-resource tmp dir; other resources are unaffected.

Output: 4 files (2 source + 2 test) under internal/cli/extract/. Reuses httpclient.Client + hash.Hash + tar.Extract from prior plans. No new go.mod entries.
