<objective>
Close CR-03: re-hydration of any adapter-written file currently fails to recognize it as "owned by current state" because the Classify path comparison mismatches. `internal/cli/extract/autoclaim.go:131` reads `entry.Target == finalPath`, where:

- `entry.Target` (from state.FileEntry) is workspace-relative — e.g. `.claude/.mcp.json` (the format documented in spec §8.2 and consistently produced by every WriteAtomic call site).
- `finalPath` (passed by `adapterDispatcherImpl.Render` at wiring.go:210) is absolute — e.g. `/workspace/.ach/.claude/.mcp.json`, built via `filepath.Join(achDir, fw.Path)`.

The two strings never compare equal. Result: every re-hydrate of an adapter-written file enters `CollisionExistsUnowned`, triggers the three-tier Cascade, and — when credentials have rotated between runs (the normal case for `ek_` deployments after rotation OR any time a pk_ holder regenerates) — exits with code 7 (CollisionRefuse). The engine refuses to update a file the engine itself wrote. The only "recovery" is `--force`, which globally suppresses SAFE-04's actual protective semantics on every other file in the same run.

Two fix paths considered:

- **(a) Store absolute paths in `FileEntry.Target` at write time.** Changes the on-disk state.json wire format. Any v2 reader that did not get the new write-time normalization would see absolute paths where it expected relative. Per D-13 (Phase 7 ships NO v1 reader and treats schemaVersion drift as a clean-break exit-5), introducing absolute paths in v2 would either (i) require a schemaVersion bump to v3 — forbidden by D-13's clean-break posture — or (ii) silently make every existing on-disk state.json incompatible with the new code. REJECTED.

- **(b) Normalize `entry.Target` to absolute inside `Classify` using `achDir` as the base.** Zero wire-format change. Single narrow fix to a single comparison. `FileEntry.Target` continues to be workspace-relative on disk; the absolute form is computed in-memory only at comparison time. ACCEPTED.

This plan does:

1. Extend `Classify`'s signature to accept `achDir string` (third positional parameter, before any future params). Inside the loop, compare `filepath.Join(achDir, entry.Target) == finalPath` (after `filepath.Clean` on both sides for path-separator/redundant-slash robustness — `filepath.Join` already cleans).
2. Update the single Classify call site in `internal/cli/hydrate/wiring.go:210` from `extract.Classify(finalAbs, s)` to `extract.Classify(finalAbs, d.achDir-or-equivalent, s)`. Note: adapterDispatcherImpl currently does NOT carry an achDir field — the dispatcher receives achDir as a parameter on `Render(ctx, m, s, achDir)`. The Classify call sits inside the per-FileWrite loop so `achDir` is already in scope at the call site; no field needs to be added.
3. Defensive: if `entry.Target` is already absolute (e.g. a future writer that stored absolute paths), reject it with a wrapped sentinel error — absolute Target is outside the spec §8.2 wire format and is treated as a tampered/incompatible state.json entry rather than allowed to bypass the achDir-relative comparison. Document the rejection in the godoc comment.
4. Add two unit tests: positive case (relative Target normalizes to match finalPath → CollisionOwnedByCurrent) and negative case (relative Target that does NOT match finalPath → CollisionExistsUnowned, no false positive). Add a third test for the absolute-Target rejection path.
5. Update the existing `autoclaim_test.go` tests if any call `Classify` with the prior two-arg signature.

Per the gap-closure quality gate (verifier's "Gaps Summary"), the runtime gate (HUMAN_VERIFICATION) is the closeout for the gap-closure cycle. The final must_have in this plan records that gate so it is not lost — the gate fires AFTER all three CR fixes (W5-01 CR-02, W5-02 CR-01, this plan CR-03) land in the tree.

Output: 1 source file modified + 1 test file extended + 1 source file modified (the wiring.go call-site update). ~25 LOC of net change. No new dependencies.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| state.json on disk → in-memory state.File | The hydrate engine reads `<ach-dir>/state.json` and trusts its `FileEntry.Target` strings as workspace-relative path keys for the autoclaim cascade. A tampered state.json could carry crafted Target values to subvert the path comparison. |
| Classify path-comparison → on-disk file outcome | The classification result (Owned / Unowned / Unmanaged) drives whether the engine overwrites a file or refuses with exit 7. A path-comparison mismatch is equivalent to a privilege error in protective intent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-W5-03-01 | Tampering | symlink races between Classify stat and subsequent rename in stage.go | accept | Classify only INSPECTS state metadata via the in-memory `*state.File`; the actual disk inspection happens later in stage.go which has its own SAFE-01/SAFE-02 surface. Classify itself does not stat the on-disk file at the path being classified — the symlink race window is bounded by stage.go's existing defenses, not introduced by this plan. |
| T-07-W5-03-02 | Tampering | `..` escape in `entry.Target` causing `filepath.Join(achDir, entry.Target)` to resolve outside `<ach-dir>` | mitigate | After `filepath.Join(achDir, entry.Target)`, apply `filepath.Clean` (Join already cleans) AND a `strings.HasPrefix(entryAbs, achDir+string(os.PathSeparator))` check (or equivalent containment test). If the normalized path escapes the achDir prefix, treat it as a non-match (do NOT return CollisionOwnedByCurrent) — preserves the autoclaim cascade's protective default of "unknown file → refuse" rather than allowing a state.json tampering to pivot the classification. Document in the godoc. |
| T-07-W5-03-03 | Tampering | absolute-Target bypass — a future writer or tampered state.json sets `entry.Target` to an absolute attacker-controlled path | mitigate | Reject absolute Target values with a wrapped sentinel error (`extract.ErrTargetNotRelative` or similar). spec §8.2 mandates relative Target; an absolute value is malformed. The third unit test in Task 1 (`TestClassifyAbsoluteTarget_Rejected`) asserts the rejection path. Document the contract in CONTEXT.md is OUT OF SCOPE — the rejection is implementation-level enforcement of the existing spec §8.2 contract. |
</threat_model>
