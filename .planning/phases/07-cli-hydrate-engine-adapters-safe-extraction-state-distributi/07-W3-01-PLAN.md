<objective>
Ship the adapter interface + registry + claude-code reference implementation. ADAPT-01 (4-adapter compile + alias resolution — claude-code first; codex/gemini/opencode are 07-W3-{02,03,04}), ADAPT-03 (runtime config rendering), ADAPT-04 (plugin canonical = Claude Code format; claude-code is pass-through), ADAPT-05 (merge strategies — claude-code uses MergeDeep for .claude/.mcp.json), ADAPT-06 (adapter scope rule — claude-code touches only .claude/), ADAPT-07 (silent-drop accounting via PluginWrite.Dropped — declared here so W3-02/03/04 don't race adapter.go).

Per D-05 + 07-CONTEXT.md `<specifics>`: claude-code is the pass-through reference; codex/gemini/opencode reference its Adapter impl for shape. This plan lands the interface + registry + claudecode together so the three remaining adapter plans (07-W3-02/03/04) can land in parallel without touching adapter.go.

Per D-07: every adapter implements ResolveOutputContent for the SAFE-04 cascade Tier 2 — pass-through adapters return source bytes verbatim (so cascade Tier 2 ≡ source byte compare for pass-through).

Per ADAPT-07: every TransformPlugin returns a PluginWrite carrying both ExtractedFiles and a Dropped []string — claudecode returns nil Dropped; codex/gemini/opencode populate it for hook/command components that have no destination in the target platform.

Per ADAPT-03 credential propagation: adapter.WithCredential(ctx, bearer) injects the Bearer token into context.Context under an unexported typed key; adapter.CredentialFromContext(ctx) reads it back. Adapters never touch env vars directly — the orchestrator (07-W3-05 wiring) wraps the credential before calling RenderRuntime.

Output: 6 files under internal/cli/adapter/ + internal/cli/adapter/claudecode/. Unit-tested with table-driven scenarios.
</objective>
