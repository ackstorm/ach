<objective>
Close CR-01: stop writing credential-bearing adapter runtime-config files at world-readable mode 0o644. `internal/cli/state/atomic.go:62` hardcodes `tmp.Chmod(0o644)` for every WriteAtomic call. WriteAtomic is the publication path for BOTH `state.json` (no secrets — 0o644 is correct) AND adapter runtime-config files via `adapterDispatcherImpl.Render` (wiring.go:230) and the three Sync inverse-merge sites (wiring.go:459, 517, 548). These adapter files embed plaintext `x-ach-key` bearer credentials in their headers maps; at 0o644 any other local user can read them and exfiltrate the bearer.

The fix is to make file mode a per-caller decision. Two approaches considered:

- **(a) Add a required `os.FileMode` parameter to `WriteAtomic`.** Changes the signature; every caller (state.Save + 4 wiring.go sites + any test) updates. The shape is honest — file mode is per-caller policy, not a package-default. This is the recommended approach because there are exactly five production call sites and one test caller, the change is mechanical, and a single signature is easier to audit than two parallel functions where future callers might pick the wrong one.

- **(b) Add a sibling `WriteAtomicWithMode(path, data, mode)` and keep `WriteAtomic(path, data)` as the 0o644 default.** Less churn but creates a footgun: a future credential-bearing caller might use the default-named function.

Pick (a). The audit cost of preventing future credential leaks outweighs the one-time churn of updating six call sites. Document the choice in atomic.go's package doc comment.

This plan does:

1. Change `WriteAtomic` signature to `WriteAtomic(path string, data []byte, mode os.FileMode) error` and use `mode` at the Chmod call (replacing the 0o644 literal). Remove the now-stale comment block at lines 59-61.
2. Update `state.Save` to pass `0o644` explicitly (it is the legitimate no-secrets path).
3. Update all four `state.WriteAtomic(...)` call sites in `internal/cli/hydrate/wiring.go` to pass `0o600` — they all touch credential-bearing files.
4. Update `internal/cli/state/atomic_test.go`: the existing `TestWriteAtomic_FileMode` asserts 0o644; extend the suite with `TestWriteAtomic_Mode0600_HonoredOnCredentialFile` to assert 0o600. Update the other existing tests to pass 0o644 explicitly through the new signature.

Output: 3 source files + 1 test file modified. ~12 LOC of net change. No new dependencies.

Purpose: a multi-user host (CI runner, shared dev box, container with shared volumes) running `ach-cli hydrate` no longer leaks plaintext bearer credentials to other local UIDs via filesystem-readable adapter configs. This is the load-bearing fix for SAFE-04's actual security posture — the verifier flagged this as a BLOCKER because the safety claim ("safe extraction rejects malicious archives") cannot coexist with "the engine's own writes leak credentials to coexisting local users."
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ach-cli process → workspace filesystem | The hydrate engine writes adapter runtime configs under `<ach-dir>` carrying plaintext `x-ach-key` bearer credentials embedded in adapter `headers` maps. |
| owner UID → other local UIDs | On multi-user hosts (CI runners, shared dev boxes, multi-user VMs, containers with shared bind mounts) any non-owner local UID can read mode-0o644 files via the standard POSIX permission model. |
| WriteAtomic temp file → final path | The publication primitive creates `<dir>/.<name>.tmp.<rand>`, chmods it, then renames to the final path. Each stage is a potential race window. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-W5-02-01 | Information Disclosure (HIGH) | adapter runtime configs at 0o644 on multi-user hosts (CR-01 BLOCKER) | mitigate | Tasks 1-2 land: WriteAtomic gains a mandatory `mode os.FileMode` parameter; all four wiring.go call sites pass 0o600. A non-owner UID running `cat ~/.ach/.claude/.mcp.json` now returns EACCES. Test `TestWriteAtomic_Mode0600_HonoredOnCredentialFile` asserts the on-disk mode via os.Stat. |
| T-07-W5-02-02 | Tampering | TOCTOU window between rename and the next caller's open | mitigate | `tmp.Chmod(mode)` runs BEFORE `os.Rename(tmp, final)` (the order documented in Task 1's action and enforced by the existing atomic.go control flow). The temp file is mode 0o600 from creation (chmod on the temp), so the final path is mode 0o600 from the instant rename completes. Accept the millisecond window between rename and first reader — the race target is the temp path with an unpredictable name, not the final path. |
| T-07-W5-02-03 | Tampering | symbolic-link race on the temp file | accept | `os.CreateTemp` uses unpredictable temp names in the same directory as the final file. An attacker with write access to that directory could pre-create a symlink at a guessed name, but the predictability is bounded by the random suffix and the same directory is the destination dir whose access is already required for the operation. Residual risk is bounded by the same-directory write requirement which the threat model treats as in-scope owner access. |
| T-07-W5-02-04 | Information Disclosure | Sync-path (inverse-merge) credential-bearing writes via the SAME WriteAtomic primitive | mitigate | Task 2 explicitly enumerates the three Sync call sites (wiring.go:459, 517, 548 — syncComposite / syncDeepJSON / syncDeepTOML) and updates them to pass 0o600. These functions read the credential-bearing file, mutate it, and re-publish via WriteAtomic — the mode contract must propagate. Acceptance criterion `grep -c "state.WriteAtomic(.*, 0o600)" internal/cli/hydrate/wiring.go` returns exactly 4 (Render + 3 Sync sites). |
| T-07-W5-02-05 | Information Disclosure | state.json mode regression — a future credential-bearing caller mistakenly uses the state.Save path | mitigate | Reject Option (b) sibling-function approach. WriteAtomic's signature carries a required `mode os.FileMode` parameter (no default in Go); every caller MUST express the mode policy at the call site. A future writer that omits the mode arg fails to compile. The acceptance criterion `grep -nE 'WriteAtomic\\([^,]+,[^,]+\\)' internal/cli/state/*.go` returning zero hits enforces this at audit time. |
</threat_model>
