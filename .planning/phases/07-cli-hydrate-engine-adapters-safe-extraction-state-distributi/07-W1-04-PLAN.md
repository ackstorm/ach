  <behavior>
    - Hash(r io.Reader) (string, error) — streams r through xxh3.New() via io.Copy; returns "xxh3:" + lowercase hex of the 16-byte (128-bit) sum
    - HashBytes(b []byte) string — convenience non-streaming form; uses xxh3.Hash128(b) directly; returns "xxh3:" + lowercase hex
    - Both forms produce identical output for identical input: Hash(bytes.NewReader(b)) == HashBytes(b)
    - The 128-bit output is encoded as 32 hex chars (16 bytes * 2 hex chars each) — Hi+Lo uint64 packed big-endian into a [16]byte then hex.EncodeToString
    - Tests use known vectors. Recommended: empty input -> known xxh3 128-bit value; "abc" -> known value; pseudo-random 1MB buffer streamed vs HashBytes -> equal. Hard-coded vectors should match xxh3.Hash128([]byte{...}) computed at task time via a small helper — DO NOT invent vectors.
    - The 1MB streaming test asserts that Hash and HashBytes agree on the same input (consistency test, not a vector test)
    - SPDX header on every *.go file
    - doc.go documents the format invariant ("xxh3:" prefix + 32 hex chars), cites D-10 + spec §8.2 + STATE-02
    - Package imports: "encoding/hex", "io", "github.com/zeebo/xxh3" — NOT crypto/* (xxh3 is not cryptographic; it's content-addressed integrity per D-14)
  </behavior>
