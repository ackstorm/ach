<objective>
Close WR-01 (warning severity, production safety): the SIGKILL injection seam at `internal/cli/hydrate/commit.go:178-182` unconditionally reads `ACH_E2E_PHASE7_INJECT_SIGKILL_AFTER_STEP` from the environment on every `newCommit()` call in the release binary. Any user (or misconfigured parent process) that sets this env var to a numeric step value causes `ach-cli hydrate` to terminate mid-flight after the named step, leaving the workspace partially mutated (state.json may be on disk but the lock fd is released without orderly cleanup; in shared CI environments where env vars are inherited across steps this is a silent data-loss vector).

The seam is intentional for the W4-01 sc2_commit_sequence_sigkill e2e subtest (deterministic SIGKILL between steps 11/12 to prove crash-safety of the atomic state write). But that test runs under `//go:build e2e` already — the env-var read does not need to exist in the release binary at all.

This plan does:

1. Split the seam into two build-tag-gated files:
   - `internal/cli/hydrate/sigkill_seam_e2e.go` (//go:build e2e) — declares the const `envSigkillStep`, the function `readSigkillSeamFromEnv() int` (reads the env var, parses int, returns 0 on any error), and `defaultKillFn(step int)` which actually invokes `syscall.Kill(os.Getpid(), syscall.SIGKILL)`.
   - `internal/cli/hydrate/sigkill_seam_prod.go` (//go:build !e2e) — stub that returns 0 from `readSigkillSeamFromEnv()` and a no-op `defaultKillFn(step int)` (immediately returns). The env var is never read; the SIGKILL never fires.
2. Replace the inline env-var read in `commit.go:178-182` with `c.injectSigkillAfterStep = readSigkillSeamFromEnv()`. Move the `envSigkillStep` const + `defaultKillFn` declarations OUT of commit.go (lines 80-84 + 86-99) into the seam files; commit.go no longer references the literal env-var name.
3. Keep the `*commit.injectSigkillAfterStep` field, the `killFn` field, and the five `c.maybeKill(N)` call sites in `run()` exactly as they are today. Under `-tags=!e2e`, `defaultKillFn` is a no-op AND `readSigkillSeamFromEnv` returns 0, so `injectSigkillAfterStep == 0` AND `maybeKill`'s existing guard (`if c.injectSigkillAfterStep != step { return }`) short-circuits before reaching `c.killFn(step)`. No production behavior change.
4. Relocate the existing tests in `commit_test.go` that exercise the seam (`TestNewCommit_ReadsSigkillSeam_ValidStep`, `TestNewCommit_ReadsSigkillSeam_InvalidIgnored`) into a new file `internal/cli/hydrate/commit_sigkill_seam_test.go` with the `//go:build e2e` constraint. Add a complementary file `internal/cli/hydrate/commit_release_build_test.go` with the `//go:build !e2e` constraint containing a single test `TestNewCommit_IgnoresSigkillEnv_InReleaseBuild` that asserts the env var is ignored in release builds.
5. Add a CLI helper assertion in `test/e2e/phase7_helpers_test.go` that documents (via a comment) that the `phase7BinaryPath` MUST be built with `-tags=e2e` for sc2_commit_sequence_sigkill to fire. Update the existing build helper (if any) to include `-tags=e2e`. NOTE: if `phase7BinaryPath` is already built via `go build -tags=e2e`, this is a no-op confirmation; if not, the helper is updated to add the build tag.

Threat model: WR-01 is a defense-in-depth fix. The seam is documented and named TEST-ONLY, but the env-var-read mechanism is a code-injection vector — any process that can set environment variables for the `ach-cli` invocation (parent shell, CI step config, a sudo'd script) can crash mid-hydrate. Build-tag gating removes the attack surface entirely from release builds.

Output: 2 new source files + 3 modified files + 2 new test files. ~40 LOC net (mostly mechanical relocation of existing seam code, plus the new build-tag stubs). No new dependencies.
</objective>
