<objective>
Close WR-03 (STATE-02 polish): the current `Load` (state.go:93-114) runs `dec.DisallowUnknownFields()` BEFORE checking `schemaVersion`. Consequence: a v1 state.json that carries the removed `contentHashes` field hits the unknown-fields check FIRST and returns `ErrStateParse` (exit 1) instead of `ErrSchemaMismatch` (exit 5). The caller (`commit.go:step3ReadState`) only bypasses the error with `--force` when `errors.Is(err, state.ErrSchemaMismatch)` — the `ErrStateParse` arm has no `--force` escape hatch.

A user upgrading from Phase 6 or earlier (when state.json had a different shape with `contentHashes`) sees:

```
error: read state.json: state: parse failed: json: unknown field "contentHashes"
```

with no recovery path documented. The CLAUDE.md failure-mode entry for "schemaVersion != \"2\"" (added by 07-W4-02) doesn't apply here because the user gets ErrStateParse, not ErrSchemaMismatch. The user must manually delete state.json (not documented in any error message) or know to pass `--force` (which currently doesn't work for this case).

The fix is a small reordering: run a non-strict `json.Unmarshal` into a `struct{ SchemaVersion string }` BEFORE the strict decode. If the schemaVersion is present and != "2", return ErrSchemaMismatch immediately. Otherwise, fall through to the existing strict-decode-with-DisallowUnknownFields path.

This plan does:

1. In `internal/cli/state/state.go:Load`, replace the body's decode block with a two-phase check:
   - Phase 1: best-effort `json.Unmarshal(raw, &sv)` into a local `struct { SchemaVersion string }`. Ignore any error (best-effort). If `sv.SchemaVersion != "" && sv.SchemaVersion != "2"`, return `fmt.Errorf("%w: got %q, want \"2\"", ErrSchemaMismatch, sv.SchemaVersion)`.
   - Phase 2: the existing strict decode with `DisallowUnknownFields` unchanged. Catches v2-with-unknown-fields (corruption, forward-compat drift).
2. Rewrite the `Load` godoc to document the new ordering.
3. Add two new unit tests:
   - `TestLoad_V1FileReturnsErrSchemaMismatch`: write a state.json on disk with `{"schemaVersion": "1", "contentHashes": {...}, ...}` (or any non-"2" version with a legacy field); assert Load returns `errors.Is(err, ErrSchemaMismatch)` AND NOT `errors.Is(err, ErrStateParse)`.
   - `TestLoad_V2FileWithUnknownFieldReturnsErrStateParse`: write a state.json with `{"schemaVersion": "2", "futureField": "..."}`; assert Load returns `errors.Is(err, ErrStateParse)` AND NOT `errors.Is(err, ErrSchemaMismatch)`.
4. Update the existing failure-mode entry for state.json schemaVersion in CLAUDE.md is OWNED BY 07-W4-02; this plan does NOT modify CLAUDE.md (the entry there already says "Delete <ach-dir>/state.json OR pass --force" — that recovery path now works under the new ordering, so the entry becomes accurate without further edits).

Output: 1 source file + 1 test file modified. ~25 LOC net (mostly the two new tests; the source change is +6 LOC for the phase-1 check, -2 LOC for the doc-comment rewrite). No new dependencies.

Purpose: make the documented `--force` recovery path actually work for v1 state.json files, as advertised by the CLAUDE.md failure-mode entry (W4-02) and the spec §8.2 clean-break decision (D-13). Without this fix, the documentation is a promise the code doesn't keep.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk state.json → state.Load decoder | An out-of-tree CLI build or a v1-era state.json file is parsed by the v2 reader. |
| state.Load error → caller exit code mapping | The error sentinel returned by Load determines whether the user gets exit 1 (general error, no recovery) or exit 5 (schema mismatch, --force overrides). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-W5-06-01 | Denial of Service | v1 state.json blocks every Phase 7+ hydrate with no documented recovery | mitigate | Reorder Load to check schemaVersion first; return ErrSchemaMismatch (exit 5) which the caller's --force path overrides. |
| T-07-W5-06-02 | Tampering | a crafted state.json with both a wrong schemaVersion AND unknown fields | accept | Phase 1 fires first; the caller sees ErrSchemaMismatch and (if --force) discards the file. The strict decode never runs on the malformed file, which is the correct outcome. |
| T-07-W5-06-03 | Information Disclosure | best-effort json.Unmarshal reading raw bytes | accept | The Unmarshal targets a struct with only `SchemaVersion string` — no other fields are parsed or stored in memory beyond the byte slice already in scope; no information disclosure surface introduced. |
</threat_model>
