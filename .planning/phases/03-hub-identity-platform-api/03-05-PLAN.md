<objective>
Wire the per-request authentication path that every Phase 3 (and Phase 4/5) component will inherit: a `Resolver` interface backed by Redis-cache→DB-on-miss with single-flight dedup, plus a chi-compatible middleware chain (RequestID, RecoverPanic, AccessLog, ContentTypeJSON, Authn). The middleware funnel ensures every authenticated handler receives a populated `KeyContext` in ctx and never sees the raw bearer plaintext.

Purpose: D-07 + D-08 + D-09 + D-02 + D-19. Centralize the cache, the single-flight, the prefix-dispatch, and the bearer-discard discipline in two packages so handlers (03-07..03-10) can write `keyCtx := KeyContextFromCtx(r.Context())` and proceed.

Output: 4 new files in new `internal/keystore/` package + 4 new files in new `internal/platformapi/middleware/` package. </objective>
