    Body: emit the LITERAL CTE shape per BLK-04 (matches REQUIREMENTS.md KEY-04 line 41 literal "single atomic SQL CTE" wording AND Hub §7.1):

    ```sql
    WITH candidate AS (
        SELECT key_id, owner_email
        FROM personal_keys
        WHERE credential_hash = $1
          AND status = 'active'
          AND expires_at > now()
        FOR UPDATE
    )
    UPDATE personal_keys SET
        last_used_at = CASE
            WHEN personal_keys.last_used_at IS NULL
              OR personal_keys.last_used_at < now() - interval '5 minutes'
            THEN now()
            ELSE personal_keys.last_used_at
        END,
        expires_at = CASE
            WHEN personal_keys.last_used_at IS NULL
              OR personal_keys.last_used_at < now() - interval '5 minutes'
            THEN now() + interval '7 days'
            ELSE personal_keys.expires_at
        END
    FROM candidate
    WHERE personal_keys.key_id = candidate.key_id
    RETURNING personal_keys.key_id, personal_keys.owner_email, personal_keys.expires_at,
              personal_keys.litellm_user_id, personal_keys.litellm_token
    ```

    Use `pool.QueryRow(ctx, sql, credentialHashHex).Scan(...)`. The CTE shape is functionally equivalent to a single UPDATE+CASE+RETURNING but matches the spec wording literally — KEY-04 zero-rows semantic is preserved because the UPDATE returns zero rows when `candidate` is empty (revoked / expired / unknown credential_hash). Handle `errors.Is(err, pgx.ErrNoRows)` → return `(nil, nil)`. Handle transient errors via `isTransientPgErr(err)` → return raw err.
