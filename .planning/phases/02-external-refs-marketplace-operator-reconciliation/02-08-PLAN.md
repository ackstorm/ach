  Land the Hub §18.4 orphan LiteLLM key cleanup Runnable (D-15, D-16, D-18). Per-tick procedure:

  1. Enumerate ACH-managed `litellm_user_id` set via `db.ListACHManagedLitellmUsers` (Plan 02-03 helper).
  2. Enumerate active ACH `key_id` set via a new `db.ListActiveACHKeyIDs` helper (this plan adds it).
  3. For each managed user, call `litellm.Client.ListUserKeys(ctx, userID)`:
     - On LiteLLM-unreachable → emit ONE audit event for the abort + return cleanly (Hub §18.4 abort-on-unreachable rule).
     - For each returned key: if key.CreatedAt < 10 minutes ago → skip (too new); if key.KeyID is in the active ACH set → skip (not orphan); otherwise → revoke + emit audit event.

  Phase 2 specifics:
  - **No live data path** — Phase 2 has no SSO write path; personal_keys + environment_keys are both empty (Phase 3 lands the writes). `db.ListACHManagedLitellmUsers` will return `[]` on every tick; the loop runs through with no LiteLLM calls and no audit events. This is the **expected steady-state** for Phase 2.
  - The interval validation (≥5min floor, default 1h) is OUTSIDE this plan's scope — it lives in Plan 02-09's cmd/operator/main.go where the new `MustEnvDurationAtLeast` helper is introduced. This plan's `NewRunnable(client, db, audit, interval, log)` constructor accepts a pre-validated `time.Duration` and trusts the caller.
  - The Phase 2 ACH DB does NOT yet record the LiteLLM-side key_id for each issued pk_/ek_ (Phase 3 will add a `litellm_key_id` column on personal_keys + environment_keys per the Hub §16.1 contract). Until then, the "absent from active ACH rows" check is approximated by checking the active ACH `key_id` set (pkid_/ekid_ prefixed values which are DISTINCT from LiteLLM-side key_ids). The orphan definition therefore degenerates in Phase 2 to "any LiteLLM key whose key_id does NOT appear in the active ACH key_id set". Since LiteLLM-side key_ids are never `pkid_`/`ekid_` prefixed (they're `sk-...`-style values), this approximation flags EVERY LiteLLM key as orphan — which is correct given Phase 2 has issued zero pk_/ek_.

The current plan's helper signature accommodates this future refactor without breaking the Runnable contract.

        r.Log.Info("orphan-cleanup Runnable starting", "interval", r.Interval)
        t := time.NewTicker(r.Interval)
        defer t.Stop()
        for {
            select {

    **TickOnce(ctx)** — the load-bearing procedure (Hub §18.4 + D-16):
    ```go
    func (r *Runnable) TickOnce(ctx context.Context) {
        // Step 1: enumerate ACH-managed user_id set.
        userIDs, err := db.ListACHManagedLitellmUsers(ctx, r.DB)
        if err != nil {
            r.Log.Error(err, "orphan-cleanup: ListACHManagedLitellmUsers failed; skipping tick")
            return
        }
        if len(userIDs) == 0 {
            r.Log.V(1).Info("orphan-cleanup: no ACH-managed users; tick is a no-op")
            return
        }

        // Step 2: enumerate active ACH key_id set (for the "absent" membership test).
        achKeyIDs, err := db.ListActiveACHKeyIDs(ctx, r.DB)
        if err != nil {
            r.Log.Error(err, "orphan-cleanup: ListActiveACHKeyIDs failed; skipping tick")
            return
        }
        achKeySet := make(map[string]struct{}, len(achKeyIDs))
        for _, k := range achKeyIDs { achKeySet[k] = struct{}{} }

        // Step 3: for each user, ListUserKeys → identify orphans → revoke.
        now := time.Now()
        cutoff := now.Add(-OrphanAgeFloor)
        for _, uid := range userIDs {
            keys, err := r.Client.ListUserKeys(ctx, uid)
            if err != nil {
                // Hub §18.4: LiteLLM-unreachable aborts the tick cleanly.
                // Emit ONE audit event characterizing the abort and return.
                r.Audit.Info("operator.orphan-cleanup",
                    "target.kind", "tick",
                    "outcome", OutcomeLiteLLMUnreachable,
                    "user_id", uid,
                    "err", err.Error())
                r.Log.Info("orphan-cleanup: tick aborted on LiteLLM-unreachable", "user_id", uid, "err", err)
                return
            }
            for _, k := range keys {
                // Skip if too new.
                if !k.CreatedAt.Before(cutoff) {
                    continue
                }
                // Skip if NOT orphan (key_id is in active ACH set).
                if _, active := achKeySet[k.KeyID]; active {
                    continue
                }
                // Orphan: revoke + emit audit event.
                if err := r.Client.RevokeKey(ctx, k.KeyID); err != nil {
                    // Per D-18 the audit event reflects the actual outcome; revoke_failed is its own audit case.
                    r.Audit.Info("operator.orphan-cleanup",
                        "target.kind", "litellm_key",
                        "target.name", k.KeyID,
                        "outcome", OutcomeRevokeFailed,
                        "user_id", uid,
                        "err", err.Error())
                    r.Log.Info("orphan-cleanup: revoke failed; continuing tick", "key_id", k.KeyID, "err", err)
                    continue  // do NOT abort the tick — sibling users may still have revokable orphans
                }
                r.Audit.Info("operator.orphan-cleanup",
                    "target.kind", "litellm_key",
                    "target.name", k.KeyID,
                    "outcome", OutcomeSuccess,
                    "user_id", uid)
                r.Log.Info("orphan-cleanup: revoked", "key_id", k.KeyID, "user_id", uid, "key_alias", k.KeyAlias)
            }
        }
    }
    ```
