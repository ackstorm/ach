The Snapshotter contract this plan PRODUCES:

```go
package snapshot

// LiteLLMSnapshot is the immutable refresh result. Reads via
// Snapshotter.Snapshot are atomic.Pointer.Load + value-copy — lock-free.
type LiteLLMSnapshot struct {
    Models     map[string]struct{}
    MCPServers map[string]struct{}
    A2AAgents  map[string]struct{}
    RefreshedAt time.Time
    Stale       bool   // true when the latest refresh failed; prior snapshot preserved with this flag set
}

// Snapshotter is the manager.Runnable that refreshes a LiteLLMSnapshot
// every Interval seconds, storing it in an atomic.Pointer for lock-free
// reads from Environment.Reconcile.
type Snapshotter struct {
    client                   litellm.Client
    interval                 time.Duration
    snap                     atomic.Pointer[LiteLLMSnapshot]
    log                      logr.Logger
    litellmUnreachableCount  atomic.Int64
}

// NewSnapshotter constructs a Snapshotter wired to a litellm.Client. The
// default interval is 5 minutes per Hub §6.4.
func NewSnapshotter(c litellm.Client, log logr.Logger) *Snapshotter

// Snapshot returns the most recent LiteLLMSnapshot value (by-value copy
// of the underlying atomic.Pointer target). Returns LiteLLMSnapshot{} on
// cold start (no refresh completed yet); callers treat every spec entry
// as unresolved in that case, which is the correct first-reconcile
// behavior.
func (s *Snapshotter) Snapshot() LiteLLMSnapshot

// Start implements controller-runtime's manager.Runnable. Runs an
// initial refresh, then ticks every s.interval. Returns when ctx is
// canceled (manager shutdown / SIGTERM).
func (s *Snapshotter) Start(ctx context.Context) error

// LiteLLMUnreachableCount returns the cumulative number of refreshes
// that failed because LiteLLM was unreachable. Phase 5 wires this into
// the litellm_unreachable_total{caller="operator"} Prometheus counter.
func (s *Snapshotter) LiteLLMUnreachableCount() int64
```

    ```go
    func (s *Snapshotter) Start(ctx context.Context) error {
        s.log.Info("litellm-snapshot Runnable starting", "interval", s.interval)
        s.refresh(ctx)                   // initial population
        t := time.NewTicker(s.interval)
        defer t.Stop()
        for {
            select {
            case <-ctx.Done():
                s.log.Info("litellm-snapshot Runnable stopping")
                return nil
            case <-t.C:
                s.refresh(ctx)
            }
        }
    }
    ```

    **refresh(ctx)** — the load-bearing function. D-14 stale-preservation contract:
    ```go
    func (s *Snapshotter) refresh(ctx context.Context) {
        models,    errM := s.client.ListModels(ctx)
        mcps,      errC := s.client.ListMCPServers(ctx)
        agents,    errA := s.client.ListA2AAgents(ctx)

        // Treat ErrNotFound (empty set) as success per Plan 02-01 SUMMARY:
        // an empty LiteLLM is a valid state, not an error.
        if errors.Is(errM, litellm.ErrNotFound) { models, errM = nil, nil }
        if errors.Is(errC, litellm.ErrNotFound) { mcps,   errC = nil, nil }
        if errors.Is(errA, litellm.ErrNotFound) { agents, errA = nil, nil }

        if errM != nil || errC != nil || errA != nil {
            s.litellmUnreachableCount.Add(1)
            // Preserve prior snapshot with Stale=true.
            if cur := s.snap.Load(); cur != nil {
                stale := *cur
                stale.Stale = true
                s.snap.Store(&stale)
                s.log.Info("litellm snapshot: upstream unreachable; preserving prior snapshot",
                    "modelsErr", errM, "mcpErr", errC, "a2aErr", errA,
                    "priorRefreshedAt", cur.RefreshedAt)
                return
            }
            // First refresh ever failed — store an empty stale snapshot so
            // callers don't oscillate between "cold start" and "stale" semantics.
            s.snap.Store(&LiteLLMSnapshot{Stale: true, RefreshedAt: time.Now()})
            s.log.Info("litellm snapshot: initial refresh failed; emitting empty stale snapshot",
                "modelsErr", errM, "mcpErr", errC, "a2aErr", errA)
            return
        }

        // All three list calls succeeded — build the fresh snapshot.
        next := &LiteLLMSnapshot{
            Models:      toModelSet(models),
            MCPServers:  toMCPSet(mcps),
            A2AAgents:   toAgentSet(agents),
            RefreshedAt: time.Now(),
            Stale:       false,
        }
        s.snap.Store(next)
        s.log.Info("litellm snapshot refreshed",
            "models", len(next.Models),
            "mcpServers", len(next.MCPServers),
            "a2aAgents", len(next.A2AAgents))
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LiteLLM REST API ↔ Snapshotter HTTP client | Three GET requests every 5 minutes carrying the LiteLLM master key via the redacting RoundTripper from internal/litellm/transport.go (Plan 02-01). No body data flows back into the operator beyond the model/mcp/agent name sets. |
| Snapshotter goroutine ↔ Environment reconciler goroutines | Many readers, single writer; coordination via atomic.Pointer.Load/Store. No mutex; concurrent reads during a Store see EITHER the old pointer OR the new pointer atomically. |
| Stale snapshot ↔ ExecutionResourcesResolved status writes | Environment reconciles continuing against a Stale snapshot emit ResourceUnresolved status conditions that reflect cached data potentially several minutes old. Hub §6.4 explicitly accepts this. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07-01 | Information disclosure | Snapshotter log messages echoing model_name or mcp_name lists that could be sensitive customer-routing names | accept | Model / MCP / agent names are deployment-configured by the operator (deployer) and are operationally-visible by design (kubectl describe environment shows them). They are not secrets — Hub §6.4 lists them as part of public condition state. |
| T-02-07-02 | Denial of service | Adversarial LiteLLM returning 10000 model entries causing huge map allocations on every refresh | accept | LiteLLM 1.83.10 schema doesn't impose a server-side cap, but a misconfigured deployment with 10000 models is unusual; map[string]struct{} memory is ~80 bytes per entry → 800 KiB worst case, well bounded. |
| T-02-07-03 | Information disclosure | EnvironmentReconciler logging spec.runtime.* names into status.message — operator could see other tenants' resource names in a multi-namespace deployment | mitigate | MULTI-01 enforces namespace-scoped informer cache; this Operator only sees CRs in its own namespace. Cross-namespace name leakage is impossible at the informer level. |
| T-02-07-04 | Tampering | A reader observing the atomic.Pointer at the exact instant of Store sees inconsistent map state | mitigate | atomic.Pointer.Load returns a *LiteLLMSnapshot; the value-receiver Snapshot() method does `return *p` which is a SHALLOW copy of the struct — the underlying map pointers are stable for the lifetime of the snapshot. Refresh creates entirely new maps; no concurrent mutation of any specific map. -race testing in Task 1 verifies this. |
| T-02-07-05 | Spoofing | A Snapshotter started with a NoopClient (Plan 01) returning (nil, nil) treats EVERY model as unresolved | accept | Per Plan 02-01 SUMMARY: NoopClient list-helpers return (nil, nil) which the Snapshotter's refresh handles cleanly: all three lists empty, snapshot stored with empty maps, NOT marked Stale. Environment.Reconcile then correctly emits ExecutionResourcesResolved=False reason=ResourceUnresolved with every spec entry in unresolvedRuntime. This is the correct unit-test / Phase 1 deployment behavior — Phase 1 Environments with non-empty spec.runtime SHOULD show unresolved until Phase 2 wires the real LiteLLM client (Plan 02-09). |
| T-02-07-06 | Denial of service | Snapshotter ticker fires while a refresh is in flight, queueing concurrent refreshes | accept | refresh(ctx) is synchronous within Start(ctx)'s for-loop body; one tick at a time. If a refresh takes longer than s.interval the next tick simply runs immediately after — no goroutine fan-out. Worst case: refreshes back-to-back with no gap. |
